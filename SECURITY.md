# Security Policy

## Reporting a vulnerability

Please do **not** open a public issue for suspected authentication, authorization, storage, database, session, or secret-exposure vulnerabilities. Contact the repository owner privately with a concise description, affected route or component, safe reproduction steps, and impact.

Do not include learner files, passwords, connection strings, OAuth codes, cookies, or access tokens in the report. The maintainer will acknowledge the report, assess severity, and coordinate remediation before public disclosure.

## Supported branch

Security fixes are applied to `main`, which is the production branch for the GitHub-to-Vercel release workflow.
